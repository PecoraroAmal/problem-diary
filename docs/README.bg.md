# Problem Diary

**Малка система, независима от използвания от вас ИИ, за поддържане на търсим дневник на решените проблеми, така че вашият ИИ асистент да спре да забравя.**

Езици: [всички езици](../README.md)

## Идеята

Ако говорите с ИИ асистент всеки ден, решавате отново и отново едни и същи видове проблеми, на много устройства и в много проекти. Асистентът не помни подробностите, а вие харчите няколко заявки, за да възстановите контекста.

Този проект води дневник в обикновен Markdown в Git хранилище. Когато проблем бъде решен, асистентът записва кратък запис: **какъв е бил проблемът, стъпките, които наистина са помогнали, и заключението** (не целия чат и не неуспешните опити). Следващия път асистентът първо чете дневника и намира отговора с по-малко заявки.

Полезен е, ако имате много проекти и устройства. Ако задавате само бързи, единични въпроси, не ви е нужен.

## Как работи

```
 чат с Claude ──"close and save"──▶ попълнена връзка ──▶ Claude Code в мрежата ──▶ commit + push
        ▲                                                                              │
        └──────── Claude Project (GitHub хранилище като знания, натиснете Sync) ◀──────┘
```

- **Запис:** Claude Code (терминал или уеб) създава записа, изпълнява `git pull`, commit и push.
- **Четене:** хранилището се добавя към Claude Project като знания. След всеки нов запис натиснете иконата Sync.
- **Без сървър и без токени в чата.** Дневникът е просто файлове във вашето хранилище, така че работи с всеки инструмент, който чете Markdown.

## Изисквания

- Собствено GitHub хранилище (частно е достатъчно), създадено от този шаблон.
- Акаунт в Claude Pro, Max или Team (необходим за Claude Code в мрежата).
- GitHub, свързан в [claude.ai/code](https://claude.ai/code), с приложението Claude, упълномощено за хранилището на дневника.
- GitHub, свързан с claude.ai (интеграцията с GitHub), за да може Project да чете хранилището.
- За дълги записи, създадени от чата: включени изпълнение на код и създаване на файлове в настройките на Claude.

## Настройка

1. Създайте **частно** хранилище от този шаблон и клонирайте или качете тези файлове.
2. Свържете GitHub в claude.ai/code и упълномощете хранилището (дайте достъп само до това хранилище).
3. Създайте Claude **Project**. В раздела за знания натиснете **+**, изберете **GitHub**, изберете хранилището и файловете, които да се включат.
4. Инсталирайте skill от `skill/problem-diary/` и в реда му `REPO:` въведете вашето `owner/име-на-хранилището`.
5. Изброете устройствата си в `diario/DEVICES.md`, с едно официално име за всяко устройство.

## Ежедневна употреба

Когато проблем бъде решен, кажете на асистента **"close and save"**. В зависимост от дължината се използва един от три пътя:

| Ситуация | Какво се случва |
|---|---|
| Кратък запис, от чата | Skill подготвя връзка `claude.ai/code` с вече попълнени prompt и хранилище. Отворете я и натиснете Enter. |
| Дълъг запис, от чата | Skill създава файла `.md` с правилното име и ви казва точната папка. Качете го от сайта на GitHub (*Add file > Upload files*). |
| Вече сте в Claude Code | Записва файла директно: `git pull`, commit, push. Без ограничение на дължината. |

След това натиснете **Sync** в Claude Project, за да виждат чатовете новия запис.

## Структура на хранилището

```
README.md                          указател на преведените README
CLAUDE.md                          инструкции за кодиращия агент
docs/README.{lang}.md              README на всеки език
diario/
  DEVICES.md                       официални имена на устройствата (едно име на устройство)
  _TEMPLATE.md                     шаблон на запис
  {device-slug}/
    YYYY-MM-DD-short-title.md      един файл за всеки решен проблем
skill/problem-diary/               skill "close and save"
  SKILL.md                         работен процес и правила
  scripts/build_link.py            изгражда попълнената връзка, проверява дължината и тайните
  assets/entry-template.md         шаблон, използван от skill (поддържайте го синхронизиран с diario/_TEMPLATE.md)
```

Проблемите, които не принадлежат към конкретно устройство (уебсайт, споделена услуга), отиват в `diario/general/`.

## Формат на записа

Всеки запис има едни и същи фиксирани заглавия, за да работят надеждно grep и търсенето с ИИ: **Date, Device, Tags, Context, Problem, Solution, Conclusion**, плюс незадължителните **Do not** и **Related**. Съдържанието го пишете на вашия език. Вижте `diario/_TEMPLATE.md`.

## Ограничения и поверителност

- Връзката носи записа в URL, така че я използват само кратките записи. По-дългите минават през файла.
- Отварянето на връзката и натискането на Enter остават ръчни: не е напълно автоматично и никой запис не се запазва, без да го видите.
- Всеки запазен запис стартира уеб сесия на Claude Code, която се отчита в използването на вашия абонамент.
- Пазете хранилището частно. Записите описват системите ви подробно.
- **Никога не слагайте пароли, токени или ключове в запис.** Напишете вместо това къде се съхраняват.
- Цялото хранилище се брои в капацитета за знания на Project. Побират се стотици кратки записи.
- Синхронизацията с GitHub в Projects понякога може да се забави или да се провали. Ако чатът не вижда нов запис, натиснете отново Sync и проверете.
